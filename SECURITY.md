# Security policy

## Scope

This policy covers the Linchuan application, its Node.js server, the native Windows desktop client, and the optional Cloudflare Tunnel setup. It does not cover the user's router, operating system, browser, Cloudflare account, or third-party runtime binaries.

## Current protections

- Joining requires a six-digit code. Join attempts are limited to 20 per source IP per minute and 30 globally per minute. Twenty cumulative wrong codes lock new joins across IP addresses and restarts. Existing sessions remain usable. Only the local service computer can refresh the code and unlock joining.
- Sessions use random 256-bit bearer tokens. HTTP sessions use an HttpOnly, SameSite cookie; HTTPS cookies are marked Secure. WebSocket connections require a valid session, matching Host/Origin, and support same-origin cookie-only handshakes.
- Private messages and files are authorized against both sender and recipient. Public messages and files are limited to authenticated members. File paths are server-generated and uploads reject symlinks, traversal names, extra multipart parts, and oversized streams.
- Uploads are streamed to temporary files, cleaned on abort, and constrained by per-device concurrency, storage budget, and a 256 MiB free-disk reserve. A shared serialized reservation budget accounts for concurrent uploads; completed writes release their reservation so written bytes are not counted twice. Multipart chunks are reserved before writing and released after the complete buffer is written. Media previews validate file signatures before decoding and write through isolated cache files.
- HTTP request bodies have a five-minute deadline. JSON bodies have a separate 15-second deadline, upload inactivity is limited to 120 seconds, and the HTTP server accepts at most 512 concurrent connections.
- API errors do not return stack traces. Responses set no-store for APIs, no-referrer, frame denial, MIME sniffing protection, and a restrictive CSP.
- Tunnel credentials are stored with Windows DPAPI for the current user. DNS tokens are entered through a masked local window and are not written to project files.
- Native session tokens also use current-user Windows DPAPI. Local host-management and desktop-identity endpoints reject forwarded internet requests; desktop-identity endpoints additionally reject browser Origin headers. Native HTTP and WebSocket requests declare `Linchuan/<version>` and retain application authentication and same-origin checks.
- Automatic native LAN routes require an authenticated group identity and a signed fresh probe. Private TLS certificates must match that group's RSA public key; public HTTPS still requires normal certificate validation. A higher host generation can replace a route, but a different group, key, or older generation cannot silently receive an existing session.
- Mobile LAN requests use an authenticated WebRTC DTLS data channel. Signaling requires an existing session; the bridge restricts methods and paths to ordinary chat/file APIs, enforces private ICE candidates, and excludes host-management endpoints. Request concurrency, upload size, frame size, peer count, and receive credits bound buffering. A service worker streams authorized file responses without caching application data or receiving session credentials. HTTPS remains the fallback when direct connection is unavailable.
- Host transfer freezes writes and copies a consistent database and committed uploads to an isolated generation directory. The source signs the transfer metadata, wraps the transfer key for the target's RSA receiving key, and encrypts chunks and tunnel credentials with AES-GCM. The receiving key is protected with current-user DPAPI so a sealed transfer can survive a receiver restart. The target verifies signatures, hashes, archive paths, storage limits, and identities before activation, then protects tunnel credentials with its current user's DPAPI. Committing atomically fences the old host; a committed transfer never automatically rolls back or re-enables old-host writes. Temporary source staging is removed after the target acknowledges activation; original data remains separate.
- The public origin is non-secret group metadata included in the database snapshot. A configured origin does not imply that the tunnel is connected. Complete native transfers require the corresponding protected credential, validate the destination group and generation, and persist the host role after activation checks. Restart recovery accepts a pending generation only after verifying the signed transfer metadata; it does not accept another group or arbitrary newer generations.
- Manual update checks use this repository's official GitHub latest-release API. Release links are restricted to HTTPS `github.com/rotcst/linchuan/releases/tag/` URLs without credentials or non-default ports. Checks do not upload application data or automatically install or run downloaded software.

## Verified checks

The repository includes isolated integration tests for authentication, Host/Origin checks, WebSocket presence and reconnect, private/public ACLs, upload boundaries, path-safe filenames, media signatures, session expiry, persistence, persistent join locking, concurrent disk reservations, and slow JSON deadlines. The 2026-10-13 local run passed 61 Node tests, including signed LAN probes, TLS/WebSocket connections, bounded WebRTC bridging, ciphertext download, host fencing, target activation, recovery metadata, public-origin snapshot/restart preservation, and explicit clearing through the actual server launcher. Online npm audit and the .NET package audit reported zero known vulnerabilities. Native core regressions cover safe payload extraction, DPAPI session persistence, pinned group certificates, transfer signature/AES-GCM tampering, host compatibility, real-service reconnect, update metadata boundaries and HTTP/WebSocket request identity. The local symbolic-link case was skipped because the test process lacked link-creation privileges. Browser regressions cover chat, media, four languages, both themes, shared dropdowns, keyboard interaction, focus styling and responsive layouts. A separate Chromium test exercises real DTLS LAN upload, streaming service-worker download, SHA-256 matching, identity persistence, and HTTPS fallback. These are isolated checks, not a guarantee against future vulnerabilities or a physical multi-device field test.

The browser and native client use cookie-authenticated WebSocket URLs. The server also accepts a query token for older clients; such clients must avoid logging credential-bearing URLs. The bundled Windows app verifies every managed file against its embedded SHA-256 manifest, refuses paths outside its managed app directory, and stages replacements before changing the installed app directory. Chat data is kept separately from managed program files.

The 1.2.1 packaged WPF regression passed 18 check groups. It exercises a real read-only preferences failure after host commit, retry and role recovery, signed pending-state recovery, receiver and activated-service restart, and public-origin menus and QR codes on both windows. Tunnel credential tests use a synthetic token with internet mode disabled; they do not verify a real Cloudflare tunnel or another physical PC.

## Limitations

Linchuan is not end-to-end encrypted: the service host can read messages and files. Initial page loading and explicit HTTP LAN pairing still use HTTP; paired automatic native routes use pinned TLS, mobile direct requests use WebRTC DTLS, and internet access uses HTTPS/WSS. Direct mobile connection needs a reachable page/signaling server and may be blocked by the browser, firewall, or router isolation. The six-digit code is a convenience gate and should only be shared with trusted people. Persistent chat and files are not disk-encrypted. A user with access to the service computer or its `data` directory can read them.

An unauthenticated visitor can deliberately trigger the join lock; the host then needs to refresh the code locally. Disk reservations coordinate Linchuan uploads, but cannot reserve space against unrelated programs writing to the same volume. This is a personal sharing service, not an isolated multi-tenant hosting platform.

The optional internet mode depends on Cloudflare and the user's account configuration. A host transfer also transfers that group's tunnel credential, so only transfer to a trusted PC and Windows user. Keep the tunnel hostname private, update Node.js and dependencies, and do not expose the data directory. The source tree intentionally excludes runtime executables, data, credentials, and QA output from version control.

Incomplete unsigned outgoing recovery records created by 1.2.0 are rejected. Preserve original data and recover that transfer explicitly; installing a newer executable cannot recreate missing tunnel credentials or merge an independent group into the original group.

The application does not keep a persistent request audit trail. Process, listener, data-count and available service-log checks can identify some anomalies, but cannot prove that no historic intrusion occurred. A local check found no suspicious service errors or unexpected application devices; it does not constitute an operating-system forensic examination.

## Reporting

Do not include join codes, session cookies, tunnel tokens, private messages, or file contents in a report. Provide a minimal reproduction, affected version or commit, request type and status, and whether the issue reproduces in an isolated temporary data directory. For suspected account or tunnel compromise, revoke the relevant Cloudflare token or tunnel credential first, then report the incident through the repository's private security channel when one is configured.
